# 系統級故障診斷（System-Level Diagnosis）

## 核心摘要

本文介紹多處理器運算系統中的 **System-Level Diagnosis**，透過節點之間相互偵測來辨識故障節點。

系統可利用 **PMC 模型** 與 **診斷度（Diagnosability）** 判斷處理單元的健康狀態。為了提升大型系統的診斷能力，也可透過 **條件診斷度（Conditional Diagnosability）** 限制特定故障分佈，降低診斷複雜度。

---

## 1. 背景與基本概念

- **運算系統構成**  
  現代電腦由大量處理單元（Processing Units）組成，並透過互連網路（Interconnection Network）連接。

- **故障類型**  
  系統運作過程中可能出現永久性或間歇性故障（Faults）。

- **診斷目標**  
  找出系統中的故障節點，以便進行替換、隔離或透過演算法繞過。

---

## 2. PMC 模型（System-Level Diagnosis）

- **提出時間**  
  1967 年，由 Preparata、Metze、Chien 提出。

- **基本原理**  
  系統內的節點透過互相測試（Mutual Check）判斷彼此狀態。

### 測試規則

| 測試節點 | 被測節點 | 結果 |
|---|---|---|
| 好點 | 好點 | `0` |
| 好點 | 壞點 | `1` |
| 壞點 | 任意節點 | `0` 或 `1` |

其中，故障節點所產生的測試結果不一定可信。

- **診斷機制**  
  收集系統中所有節點的測試結果並建立狀態表。若不同故障組合所產生的結果可以區分，則系統能正確判斷故障節點。

---

## 3. 診斷度（Diagnosability）

- **定義**  
  診斷度 `t` 表示系統最多能保證正確辨識的故障節點數量。

- **限制**
  - 節點數增加時，可能的故障組合會快速增加。
  - 使用窮舉方式建立狀態表時，資料量會大幅成長。
  - 當故障節點數量超過診斷度 `t` 時，可能無法區分不同故障模式。

### Hypercube 範例

若某系統的診斷度為：

```text
t = 3
```

代表系統最多能保證辨識 3 個故障節點。

當故障節點增加到 4 個以上時，診斷結果可能出現不確定性。

---

## 4. 條件診斷度（Conditional Diagnosability）

- **目的**  
  透過限制故障分佈，排除較極端的故障情況，提升系統診斷能力。

- **核心假設**  
  不允許出現：

> 某個節點是正常的，但與它相連的所有鄰接節點全部故障。

- **意義**
  - 排除部分極端故障模式
  - 減少需要分析的狀態數量
  - 提高故障節點較多時的可診斷性
  - 提升整體診斷效率與容錯能力

---

## 總結

System-Level Diagnosis 透過節點間的互相測試來判斷故障位置。

**PMC 模型** 提供基本的測試規則，**Diagnosability** 表示系統最多能辨識多少個故障節點，而 **Conditional Diagnosability** 則透過限制故障分佈，提升大型系統的診斷能力與效率。
