# 系統級故障診斷（System-Level Diagnosis）

## 核心摘要

系統級故障診斷（System-Level Diagnosis）主要應用於多處理器運算系統中，透過節點之間的相互測試，判斷各處理單元是否發生故障。

其中，**PMC 模型（Preparata-Metze-Chien Model）** 是經典的系統級診斷模型，藉由節點間的測試結果建立故障判斷依據，並透過 **診斷度（Diagnosability）** 衡量系統最多能正確辨識多少個故障節點。

隨著系統規模增加，傳統診斷方法的複雜度也隨之提高，因此進一步提出 **條件診斷度（Conditional Diagnosability）**，透過限制不合理的故障分佈情況，提高大型互連系統的故障診斷能力。

---

## 1. 背景與基本概念

### 運算系統架構

現代多處理器系統通常由大量的 **處理單元（Processing Units）** 所組成，並透過 **互連網路（Interconnection Network）** 進行資料交換。

當系統規模逐漸增加時，部分節點發生故障的機率也會提高，因此需要一套有效的方法判斷：

- 哪些節點正常
- 哪些節點發生故障
- 系統是否仍能正常運作
- 是否需要進行節點替換或路徑繞過

### 常見故障類型

系統中的故障主要可分為：

- **永久性故障（Permanent Fault）**  
  節點損壞後持續處於異常狀態。

- **間歇性故障（Intermittent Fault）**  
  節點可能在正常與異常狀態之間不定期切換。

### 診斷目標

系統級故障診斷的主要目標是：

> 透過系統內部節點之間的測試結果，辨識並定位故障節點。

確認故障節點後，可以進一步進行硬體替換、隔離故障節點，或透過演算法重新規劃資料傳輸路徑。

## 2. PMC 模型

### PMC Model

PMC 模型由 **Preparata、Metze 與 Chien** 於 **1967 年**提出，是系統級故障診斷中非常重要的模型之一。

其核心概念為：

> 讓系統內的節點彼此進行測試，再根據所有測試結果推論出哪些節點發生故障。

假設節點 `u` 對節點 `v` 進行測試：

```text
Node u  ───── Test ─────>  Node v
 Tester                   Tested Node
```

### 測試結果規則

在 PMC 模型中，測試結果可表示為：

| 測試節點 | 被測節點 | 測試結果 |
|---|---|---|
| 正常 | 正常 | `0` |
| 正常 | 故障 | `1` |
| 故障 | 正常 | `0` 或 `1` |
| 故障 | 故障 | `0` 或 `1` |

其中：

- `0`：表示測試結果判定節點正常
- `1`：表示測試結果判定節點故障

需要特別注意的是：

> **故障節點所產生的測試結果不可信任。**

也就是說，當測試者本身已經發生故障時，不論被測節點實際狀態為何，測試結果都可能是 `0` 或 `1`。

### 診斷機制

系統會收集所有節點之間的測試結果，形成一組完整的測試狀態。

例如：

```text
P0 → P1 : 0
P1 → P2 : 1
P2 → P3 : 0
P3 → P0 : 1
```

接著根據這些測試結果，比對可能的故障節點組合。

如果兩種不同的故障組合 **不可能產生相同的測試結果**，則系統可以正確區分這兩種故障狀態。

## 3. 診斷度（Diagnosability）

### 定義

診斷度通常以 `t` 表示。

`t` 的意義為：

> 系統在任何不超過 `t` 個節點發生故障的情況下，都能唯一且正確地辨識故障節點。

例如：

```text
t = 3
```

代表系統最多可以保證正確診斷 **3 個故障節點**。

如果實際故障節點數量超過 `3`：

```text
Fault Nodes > 3
```

則可能存在多組不同的故障狀態，產生相同或無法區分的測試結果，因此無法保證診斷正確。

### 傳統診斷方法的限制

當系統節點數量增加時，可能的故障組合也會快速增加。

若系統共有 `N` 個節點，而最多考慮 `t` 個故障節點，可能需要考慮的故障組合數約為：

```text
C(N,0) + C(N,1) + C(N,2) + ... + C(N,t)
```

因此，大型系統若直接使用窮舉方式建立故障狀態表，資料量可能快速增加至數千甚至數萬種狀態。

主要問題包括：

- 狀態表快速增加
- 搜尋與比較時間增加
- 記憶體需求提高
- 大型系統診斷效率下降

---

## 4. Hypercube 診斷範例

**Hypercube（超立方體）** 是平行運算與互連網路中常見的拓樸結構。

例如某 Hypercube 系統的診斷度為：

```text
t = 3
```

代表：

```text
故障節點 ≤ 3
        ↓
可以保證正確診斷
```

但如果：

```text
故障節點 = 4
        ↓
可能出現無法區分的故障模式
        ↓
無法保證正確診斷
```

因此，診斷度可以視為衡量系統 **故障辨識能力** 的重要指標。

---

## 5. 條件診斷度（Conditional Diagnosability）

### 為什麼需要條件診斷度？

傳統診斷度會考慮所有可能的故障組合，其中包含一些在實際系統中極少發生的極端故障狀態。

這些極端情況會降低系統理論上的診斷能力。

因此，研究者提出：

**Conditional Diagnosability（條件診斷度）**

透過加入合理的故障條件，排除極端故障組合。

---

## 6. 條件診斷的核心假設

其中一項常見的條件為：

> 不允許一個正常節點的所有鄰接節點同時發生故障。

例如：

```text
        F
        |
    F -- G -- F
        |
        F
```

其中：

- `G`：正常節點（Good Node）
- `F`：故障節點（Faulty Node）

如果正常節點 `G` 周圍所有相連的節點全部故障，就可能造成非常困難的診斷情況。

Conditional Diagnosability 會將這類極端故障分佈排除。

合理情況則例如：

```text
        G
        |
    F -- G -- F
        |
        G
```

正常節點仍至少與部分正常節點保持連接，使系統可以取得更多可信任的測試資訊。

---

## 7. 條件診斷度的優點

加入條件限制後，可以排除大量不合理或低機率的故障模式，因此具有以下優點：

### 提高診斷能力

傳統診斷度：

```text
所有可能故障組合
        ↓
部分狀態無法區分
        ↓
診斷度受到限制
```

條件診斷度：

```text
加入合理條件
        ↓
排除極端故障狀態
        ↓
減少模糊情況
        ↓
提高可診斷故障數量
```

### 降低診斷複雜度

由於部分不合理的故障組合被排除，因此需要分析的狀態數量也會減少。

可降低：

- Fault Table 大小
- 狀態搜尋範圍
- 故障模式比較次數
- 系統診斷所需時間

### 提升大型系統的容錯能力

Conditional Diagnosability 特別適合大型互連網路，例如：

- Multiprocessor Systems
- Hypercube Networks
- Mesh Networks
- Torus Networks
- Data Center Networks
- Parallel Computing Systems

在合理的故障假設下，可以讓系統容忍更多故障節點，同時仍維持可診斷性。

---

## 8. 傳統診斷與條件診斷比較

| 項目 | Traditional Diagnosability | Conditional Diagnosability |
|---|---|---|
| 中文名稱 | 傳統診斷度 | 條件診斷度 |
| 故障模式 | 考慮所有故障組合 | 排除不合理的故障組合 |
| 診斷能力 | 較低 | 通常較高 |
| 狀態數量 | 較多 | 較少 |
| 診斷複雜度 | 較高 | 較低 |
| 大型系統適用性 | 較受限制 | 較佳 |

## 9. 整體流程

```text
Processing Units
        │
        ▼
Interconnection Network
        │
        ▼
Nodes Test Each Other
        │
        ▼
Collect Test Results
        │
        ▼
Analyze Fault Patterns
        │
        ├── Traditional Diagnosability
        │
        └── Conditional Diagnosability
                    │
                    ▼
           Identify Faulty Nodes
                    │
                    ▼
        Isolation / Replacement / Rerouting
```

## 結論

System-Level Diagnosis 的核心概念，就是利用 **系統內節點彼此之間的測試結果來判斷故障位置**。

PMC 模型提供了系統級診斷的基本架構，而 **Diagnosability** 則描述系統最多能保證辨識多少個故障節點。

然而，隨著系統規模擴大，可能的故障組合會快速增加，因此透過 **Conditional Diagnosability** 對故障分佈加入合理限制，可以排除極端情況，降低診斷複雜度，並進一步提高系統能夠容忍與辨識的故障節點數量。

簡單來說：

> **Traditional Diagnosability：考慮所有可能的故障情況。**  
> **Conditional Diagnosability：排除不合理的極端故障情況，換取更高的診斷能力。**
